# Dashboard component reconstruction: frozen pilot specification

Date: 2026-09-25. This is the implementation contract for this local visual
pass, not owner approval or a rollout decision. The original 1491 × 1055 target
sets component treatment; existing authorized sources set the facts. Keep the
current 2 : 1.35 : 1 main grid, branding, actions and safety boundaries.

| Component | Final content and low-count treatment |
| --- | --- |
| Action Center | Exactly two positive, source-backed groups in order: recorded overdue remaining balance with fee-period count, then branch-wide fees due today count (including expected fees). Use one full-width section with two equal, shallow cards; one card may span when only one group exists. Zero groups show the existing truthful calm, unknown or restricted state. No invented alerts. |
| Summary row | Exactly four distinct cards: Collected this month, Active students, Shift slot utilization, Present today. Values lead; brief source-backed supporting text only. Do not add comparison trends or duplicate financial totals. |
| Collections | One actual 14-day daily-collections bar series derived from consecutive all-time cumulative observations. An optional 7-day view filters that same real series. Show explicit range, grid/axis, a single-series legend and a three-part strip for Billed this month, Collected this month and Outstanding today, labelled as independent measures rather than parts of one total. |
| Seating | A current, per-shift slot-fill tile matrix: eight equal visual bins per configured shift, with exact allocated/capacity numbers alongside and a clear scaled-share legend. Tiles are not named physical seats or historical days. Attendance remains a separately labelled section with its own service counts/date. Missing shift detail is unavailable, never inferred from physical seats. |
| Upcoming fees desktop table | Student, Fee type (Monthly/Admission), Due date, Amount, State (Expected/Recorded). The panel-level View all opens the actual fee queue; no per-row collection or contact action is invented for projected fees. |
| Follow-ups desktop table | Selection, Student, Due date, Remaining balance, recorded contact outcome/next-contact date when returned, and the existing authorized exact-payment action. Retain oldest-first order, bulk selection and full-queue links. |
| Activity | Only recorded collection, student-profile creation and seat-allocation events with actual timestamps; concise icon/title/detail/time rows. No colour-coded fictional event types. |
| Quick Actions | Exactly two secondary, capability-gated actions in a compact two-column button grid: Assign seat and Review shifts. Add student and Review payments stay in the heading; Collect remains tied to a specific fee. |

The target's scheduled-contact count, inferred attendance gaps or absence,
membership expiry/plan status, utilization alarm/optimization, weekday occupancy
history, stacked pending/collection series, collection-rate line, period-on-period
comparison, Tasks, generic Record payment and extra export controls have no
complete authorized source or action contract here. They stay absent. The
photograph and quotation blocks also remain excluded by the owner.

Changes in this pass are presentation-only. Do not alter server authorization,
tenant scope, fee definitions, collection idempotency/recovery, permissions,
language boundaries, public pages, backend, schema, environment or providers.
